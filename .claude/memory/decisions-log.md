## قرارات مقفلة (لا تغيير بدون إذن صريح)

### [PRE-001] التسعير يدوي — ليس تلقائي
**القرار:** المشرف يدخل السعر يدوياً بعد مراجعة الطلب
**السبب:** طلب العميل الصريح
**التأثير:** لا estimated_price في الـ UI — حقل quoted_price فقط — فلو: PENDING_PRICING → إيميل → قبول/رفض

### [PRE-002] Stack التقني
**القرار:** NestJS + Prisma + PostgreSQL 16 + Redis + Flutter + Next.js 14
**السبب:** اتحدد في TECH.md
**التأثير:** لا تغيير في أي جزء من الـ stack

### [PRE-003] B2B فقط
**القرار:** النظام للشركات فقط، لا أفراد

### [PRE-004] GPS من موبايل السائق
**القرار:** لا hardware GPS — السائق يفتح تطبيق Flutter ويبث موقعه

### [PRE-005] لا رفض رحلة من السائق
**القرار:** الإسناد مباشر وإلزامي

### [PRE-006] Multi-stop Shipments
**القرار:** الشحنة يمكن أن تكون متعددة النقاط
**التأثير:** جدول order_stops مستقل

### [PRE-007] Flutter للموبايل + Next.js للويب
**القرار:** Flutter (Android + iOS) للعميل والسائق — Next.js للـ Web Application
**السبب:** طلب العميل الصريح — تطبيق ينزل على Google Play + App Store

## قرارات الـ Session الحالية

### [DEC-003] الـ 5 أدوار على كلا المنصتين
**القرار:** كل دور (عميل + سائق + مشرف + محاسب + ورشة) يقدر يخش من Flutter App أو Web App
**السبب:** نفس الديزاين + نفس اللوجين + نفس الـ API — المستخدم يختار المنصة اللي يريحه
**التأثير:**
- Flutter App: تبني شاشات الـ 5 أدوار كلهم
- Web App: تبني pages الـ 5 أدوار كلهم
- Backend API: لا تغيير — نفس endpoints تخدم الاتنين

---

### [DEC-002] دمج Admin في Supervisor — 5 أدوار فقط
**القرار:** لا يوجد دور Admin منفصل — SUPERVISOR يجمع العمليات + إدارة الموظفين + التعريفة
**السبب:** شاشة اللوجين في الديزاين تُظهر 5 مسارات فقط: عميل / مشرف / سائق / محاسب / ورشة
**التأثير:**
- RBAC: 5 أدوار (CUSTOMER, DRIVER, SUPERVISOR, ACCOUNTANT, WORKSHOP)
- SUPERVISOR لديه صلاحيات إضافية: إضافة موظفين + تعريفة الأسعار + Audit Log
- Login screen: الـ dropdown يظهر "مشرف / مدير عمليات" كدور واحد
