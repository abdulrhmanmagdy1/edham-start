# دليل التجربة — تدفّقات المستخدمين (User Flows)

> سيناريوهات تجربة يدوية للنظام كاملاً. بيانات الدخول في `credentials.md` (dev-only).
> الويب: http://localhost:3000 · الـ API: http://localhost:3001/api/v1
> **ملاحظة التسعير (PRE-001):** لا يظهر أي سعر للعميل قبل أن يُدخله المشرف يدوياً.

---

## أ) العميل (Customer)

### 1) دخول العميل عبر OTP
1. افتح http://localhost:3000 → اختر "عميل".
2. أدخل الجوال `+966500000101` → "إرسال الرمز".
3. خذ الـ OTP من console الـ API (`[MOCK SMS] OTP`) → أدخله → دخول.
✅ يفتح على "طلباتي".

### 2) إنشاء طلب شحن جديد (بلا سعر)
1. "طلب شحن جديد" → حدّد نقطة الاستلام والتسليم على الخريطة (MapPicker).
2. اختر نوع البضاعة + المركبة + الوزن + (اختياري) سلسلة تبريد + التاريخ.
3. "إرسال" → لا يظهر أي سعر.
✅ الطلب يُنشأ بحالة "بانتظار التسعير".

### 3) قبول السعر
1. بعد أن يسعّر المشرف (سيناريو ب-2)، افتح الطلب (حالته "بانتظار موافقتك").
2. يظهر السعر + "غير شامل الضريبة 15%" → "قبول".
✅ الحالة → "مؤكّد — بانتظار الإسناد".

### 4) رفض السعر
- بدل القبول اضغط "رفض" → الحالة → "ملغى".

### 5) تتبّع الشحنة
1. لطلب نشط (ASSIGNED/IN_TRANSIT) افتح "تتبّع".
✅ خريطة بموقع المركبة + قائمة المحطات + الحالة. (يتحدّث لحظياً عند بث السائق موقعه — realtime).

### 6) عرض الفواتير
- "فواتيري" → قائمة (المتأخرة بالأحمر).

---

## ب) المشرف (Supervisor)

### 7) دخول + لوحة KPIs
- اختر "مشرف" → `supervisor@edham.sa` / `Edham@2026`.
✅ لوحة: بانتظار التسعير / مؤكّدة / في الطريق + آخر الطلبات + مؤشّر 🟢 "مباشر".

### 8) تسعير طلب يدوياً
1. "إدارة الطلبات" → فلتر "بانتظار التسعير" → افتح طلباً.
2. أدخل السعر + ملاحظات → "تحديد السعر".
✅ يُرسَل للعميل (يظهر في mock email بالـ console) + الحالة → PRICED.

### 9) إسناد سائق ومركبة
1. افتح طلباً حالته "مؤكّد من العميل".
2. اختر مركبة متاحة (متوافقة حرارياً) + سائقاً → "إسناد".
✅ الحالة → ASSIGNED + إشعار للسائق.

### 10) الخريطة الحية للأسطول
- "الخريطة الحية" → مواقع المركبات (fleet).

### 11) إدارة المستخدمين
- "المستخدمون" → إضافة سائق/محاسب/ورشة + تفعيل/تعطيل.

### 12) إدارة المركبات + التقارير + سلسلة التبريد
- "المركبات" → إضافة/تعديل حالة. "التقارير" → طلبات/أسبوع + إيرادات/شهر + أداء السائقين. "سلسلة التبريد" → نسبة الالتزام.

---

## ج) السائق (Driver)

### 13) تنفيذ رحلة كاملة
1. اختر "سائق" → `DRV-001` / `Edham@2026`.
2. افتح الرحلة النشطة → "تأكيد التحميل" → "بدء الرحلة".
3. سجّل درجة حرارة (للمبرّدة) → لو خارج النطاق يظهر تحذير أحمر.
4. لكل محطة: "تسليم المحطة" (+ اسم المستلم).
✅ آخر محطة → الرحلة "مكتملة" + الطلب "مكتمل" + المركبة تعود "متاحة".

### 14) الإبلاغ عن مشكلة
- "الإبلاغ عن مشكلة" → وصف → يصل إشعار للمشرف.

---

## د) المحاسب (Accountant)

### 15) إصدار فاتورة + إرسال + تسجيل دفع
1. اختر "محاسب" → `sara@edham.sa` / `Edham@2026`.
2. تبويب "جاهزة للفوترة" → طلب مكتمل → "إنشاء فاتورة" (VAT 15% تلقائي).
3. افتح الفاتورة (DRAFT) → "إرسال للعميل" → الحالة SENT (تاريخ استحقاق = +شروط الدفع).
4. "تسجيل الدفع" (+ رقم مرجع) → PAID.
✅ الفاتورة مدفوعة.

---

## هـ) الورشة (Workshop)

### 16) طلب صيانة → إكمال + تكلفة
1. اختر "ورشة" → `saad@edham.sa` / `Edham@2026`.
2. "طلب صيانة جديد" → اختر مركبة + النوع + الوصف.
3. افتح الطلب → "بدء التنفيذ" (المركبة → في الصيانة) → "إكمال" (+ التكلفة) → المركبة تعود "متاحة".

---

## و) دورة كاملة End-to-End (من الإنشاء للدفع)

### 17) الدورة الكاملة
1. **عميل:** ينشئ طلباً (بانتظار التسعير).
2. **مشرف:** يسعّره → يرسله.
3. **عميل:** يقبل السعر → مؤكّد.
4. **مشرف:** يُسند سائقاً + مركبة → ASSIGNED.
5. **سائق:** تحميل → بدء → حرارة → تسليم → مكتمل.
6. **محاسب:** ينشئ الفاتورة → يرسلها → يسجّل الدفع.
✅ الطلب مرّ بكامل دورة الحياة، والفاتورة مدفوعة.
